# 学习状态、历史摘要与原话核对

更新于：2026-10-20 09:53（Asia/Shanghai，UTC+08:00）。

上下文管理第二阶段已实现，继续以讲清楚当前困惑为目标。本文介绍同会话状态与摘要；第三阶段的显式主题接续已实现，见[学习记忆说明](learning-memory.md)，空间之间不自动互通。

## 用户怎样使用

正常提问和追问即可。Agent通过`deliver_explanation`同时交付答案、讲解记录与可选状态更新，保存当前目标、主题、具体卡点、待解释问题、近期讲法和历史查阅位置。

展开“当前学习记录”，可修正目标、主题和卡点，添加或关闭待解释问题。勾选“固定此目标，切换话题时保留”后，临时换题仍能正常讲解，但Agent不能覆盖这个目标；取消固定后可随对话调整。固定是执行器校验的用户控制，不依赖模型对换题意图的猜测。

用户明确填写与Agent工作判断分别标注。聊天中提取出的目标即使附原话，也仍是Agent解释；理解反馈只针对其关联回答。自动标记“用户表示理解”必须有指向该问题来源回答的`understood`反馈，复述核对不会自动推断整章掌握。用户可直接关闭问题。

修改带版本校验；其他页面已更新或会话正在回答时，会提示刷新或等待。清空工作状态保留原始消息与资料，也使旧摘要失效；之后可重新建立工作状态。它不等于删除聊天数据。

## 历史怎样压缩

每次Agent模型调用前仍执行[第一阶段预算管理](context-management.md)。出现历史正文被缩减的压力，且较上一次摘要尝试有足够新的已完成回合时，才考虑生成摘要。默认保留最近3轮，新的覆盖范围至少增加4轮；这不表示固定每4轮调用摘要模型。

每个用户回合最多一次摘要尝试。摘要输入有独立代理预算、30秒超时与输出预留，并受整轮总时限约束。失败或超时不覆盖旧有效摘要，沿用第一阶段裁减继续问答；同一覆盖范围不反复远端重试。超时可能没有usage，不据此认定没有产生费用。

摘要最多8项，类型分为用户原话、过去的解释、待澄清事项、资料待查位置。每项有来源运行ID；用户原话类型必须附实际出现在输入中的逐字引文。服务端校验类型、长度、来源归属及引文，不把结构合法当作语义忠实的保证。

压缩只读取已完成回合的可见用户/最终答案，原生不透明项目、隐藏推理和图片不进入摘要。每次更新从原档案重读少量旧要点的来源和新的回合，避免递归压缩旧摘要正文。过长的单条原话或答案整条省略并记录长度，不截断公式拼成新结论；预算不足时减少提供的消息，并保留来源清单供回读。

摘要记录覆盖水位、所选来源、提供的原话长度、策略、模型配置、状态版本与usage。它概括的是所选原话，不能保证保留全部历史细节。用户修正状态会改变`context_epoch`并使旧摘要失效；一般讲解更新状态版本不会导致摘要每轮重新生成。极端预算压力下摘要本身也可能移出输入，诊断会记录原因。

## 如何核对来源

网页“历史摘要与来源”展示摘要项，并链接原回答。Agent可用`recall_learning_context`读取当前会话的可见原话：指定`run_id`或`turn_seq`，选择用户或助手，按字符偏移每次读取最多4000字符，返回总长度和省略标识。读取受工具次数与上下文预算限制，跨会话时仅可读取本轮实际召回记忆明确链接的已完成来源回合，详见第三阶段说明。

原话与摘要都不是课程事实核实。精确数字、公式或图像细节仍需实际调用资料工具；历史位置附观察来源、资料版本和是否过期的标记，不因摘要出现位置就升级为当前视觉观察。

## 实现入口

| 位置 | 职责 |
| --- | --- |
| `learning.py` | 严格状态补丁、明确填写/工作假设区分、目标固定与反馈范围校验 |
| `summaries.py` | 有限原话选择、单次摘要调用、来源与逐字引文校验、失败退路 |
| `context.py` | 在完整工具组之间插入摘要，记录覆盖与省略，保护当前必要输入 |
| `store.py` | 状态版本、摘要尝试、原话读取、答案/笔记/有效状态同事务保存 |
| `agent.py` | 按观察选择行动，执行状态与原话工具，记录摘要请求的独立usage |

SQLite新增`learning_states`和`context_summaries`，旧笔记可初始化为工作假设。原有学习接口保留旧字段，增加`state/revision/summary`；`PATCH /api/conversations/{id}/learning`修改状态。API写入目标但未提供`goal_pinned`时默认固定，网页按复选框值提交；可显式设为false解除固定。清空后不从旧笔记自动重新初始化。

## 验收与限制

使用本机已有的CS231n优化课件物理14/15页：

```bash
uv run python examples/evaluate_learning_context.py data/acceptance/optimization.pdf \
  --turns 24 --budget 40960
```

此命令会调用配置的模型并计费，报告与数据库保存在`data/evaluations/`。套件覆盖用词纠正、换例子、错误复述、换页、旧回答反馈、目标修改、主题切换和早期原话回读；它不是自动教学成绩测试。

本轮记录区分首次实验与修复后的复测：

| 验收 | 结果 |
| --- | --- |
| 首次24轮 | 24轮完成，31次讲解模型返回、5次摘要返回；发现换题覆盖明确目标的问题 |
| 原话匹配调整 | 从第13轮完成状态复制后接续11轮，发现逐字匹配仍会把话题当成目标 |
| 固定目标修复 | 从相同第13轮状态另建副本接续11轮，目标11轮全部保留，话题仍正常切换 |
| 最终接续的调用 | 13次讲解返回、3次摘要返回；输入usage累计109607、输出5380，约148.88秒 |
| 早期回读 | 第20轮实际调用原话工具读取第一轮，并正确区分最初目标与面板修改后的固定目标 |
| 网页 | 修改、添加/关闭问题、清空、固定目标、刷新恢复通过；控制台无错误 |
| 工程回归 | 89项通过，包括摘要超时/服务失败退路、来源校验、版本冲突、跨会话读取拒绝与目标固定 |

三个实验分别保留，复测没有重发前13轮，也不把复制前缀计为新的调用。最终版没有另做一套从零开始的24轮重跑；摘要原话省略策略的收尾调整未改变这组已提供的短原话内容。内容复核由开发过程对照原页和对话进行，不是独立盲评，也不证明用户已经学会。没有未压缩同题付费A/B，不能据此宣称降本比例或教学收益。

真实调用仍使用配置的兼容Chat Completions网关；Responses保持离线验证边界。摘要有额外成本与延迟，可能遗漏旧细节或错误概括；原话回读、当前状态和重新查资料共同支撑接续。本阶段不含跨会话记忆；该能力已在第三阶段实现。[Agent Runtime RT1](agent-runtime.md)已支持持久提交、进度与取消；账户权限、问答中间步骤续跑仍未实现。
