# 学习反馈与连续讲解

目标是让用户暴露具体误解后，Agent调整讲解，而不是把同一答案越写越长。来源检索、看图和回听继续服务于解释；本阶段没有增加强制测验或固定检索流程。

## 使用流程

1. 上传课程资料，在会话中提出困惑；也可先选择PDF页面或视频片段。
2. 在讲解下点击“这一步没懂”“换个例子”或“我来复述”，填写卡点或自己的理解，再发送。选中的正文可带入草稿；数学渲染文本不保证与原始Markdown逐字相同，所以它被视为用户指出的卡点。
3. Agent决定澄清、补前置知识、拆推导、改用例子或类比、补查资料，围绕当前误解回答。已经有足够信息时可直接解释。
4. 理解后可点“这一点明白了”，或用自由文字反馈。要求暂停时不会固定追加测验。
5. 展开学习记录查看最近知识主题、工作判断、尝试过的讲法和明确提交的反馈；点击“返回对应讲解”回访。刷新仍保留。纠正工作判断可直接在下一条消息说明。

按钮只准备草稿，发送后才写入反馈。每条快捷反馈关联当前会话中某次已完成回答；不能引用其他会话或失败回答。自由文字追问始终保存在消息中并参与后续上下文；快捷反馈另存结构化类型与目标回答。

## 工作记录与理解反馈

两者分开保存：

| 内容 | 来源与含义 |
|---|---|
| 用户反馈 | 用户提交的类型、卡点原文、消息与对应回答；“明白了”是该范围的自述 |
| 主题与卡点 | Agent根据输入与观察形成的可修正判断 |
| 讲解策略 | 本轮采用的解释、澄清、补前提、推导、例子、类比、资料核对、复述检查或确认反馈 |
| 掌握情况 | 不从回答完成、点击按钮或一次复述自动推导客观掌握分数 |

确认理解不改变正在记录的知识主题；对旧回答的确认不覆盖新主题的卡点。新会话不会自动继承其他会话的判断。这里是会话工作记录，没有实现跨课程长期学习画像。

最终通过 `deliver_explanation` 同时提交Markdown答案和简短主题/卡点/策略记录；执行器将它们在同一数据库事务保存，不再额外调用一次模型来补笔记。交付工具须独立于阅读工具调用，防止尚未看到观察就声称完成。检索、看图和讲法仍由模型自主决定，交付格式不规定教学步骤。

旧模型或预算用尽时返回普通正文仍可显示，但不会凭空补写工作记录。执行失败保留用户反馈，保持此前成功记录；不会把未交付的策略记成已完成尝试。记录是简短可见的工作摘要，不是模型内部思维链。

默认提示首答围绕当前卡点，局部追问避免重述整章；公式与代码会增加原始字符数，不做机械截断。复杂推导可能仍长，用户可明确要求展开或缩短。

## 检索问题修正

明确课程编号如 `CS336` 同时出现在用户查询与资料文件名时，检索器据此限定候选资料，并从内容查询中移除这个标识，防止封面靠课程名得分。编号来自用户输入和文件元数据，没有写入RoPE等答案关键词，也没有降低相似度阈值。没有明确匹配时搜索原空间；中英查询改写和限定具体资料仍由Agent选择。工具观察包含实际搜索范围与内容查询。

在原先固定的10条有参考位置题上，预设位置Hit@5由70%变为80%，问题和参考标注未改。RoPE首查返回对应课程的视频片段，但仍未命中预设PDF页；完整任务中Agent自行改写查询并实际查到第31–33页。参考位置没有穷尽相关视频，指标不等于完整证据召回率。

## 连续课程验收

`examples/suites/learning_feedback.json` 固定3组，每组4回合：首次解释、暴露误解、复述检查、局部理解反馈并暂停。反馈是人工编写的模拟学习者输入，调用真实模型与真实课程材料，不冒充真人学习研究。

| 案例 | 需要识别的误解或前提 |
|---|---|
| CS336 RoPE | 旋转不是拼接位置编号；相对位置不变须固定旋转前内容向量 |
| CS336运算与耗时 | 同一GPU不代表可按运算次数分配总时间；12.75%估算不能当A100实测 |
| 中文AI Agent | 工具观测改变上下文不等于训练；调用成功不保证内容真实 |

参考要点只用于运行后的内容复核，不进入模型提示。原始报告分别记录问题、反馈、回答、策略记录、实际调用、引用、延迟和usage。内容复核由执行Agent对照课件与字幕完成，不是独立人工评分，也不报告真实理解率。

本轮有两个需要保留的尝试：最初将笔记设为可选工具，12回合虽能解释并纠错，但工作记录保存为0/12；改成答案与记录共同交付后，同样12回合完成，12/12保存记录。两轮原始数据留在本机，不用工具定义或mock测试代替这项实测。

最终运行中，RoPE追问改用二维箭头例子；运算耗时追问给出可手算的搬运/计算表；工具任务逐点指出复述的正确与错误部分。3次暂停反馈均简短确认，没有强制继续出题。10个位置引用全部可解析，不能据此保证所有语义归因都正确。中文专业术语、复杂首答长度和模型判断稳定性仍需更多真实使用反馈。

本轮41项工程测试通过，包括反馈会话边界、交付顺序、失败不提交记录、旧回答反馈不覆盖新主题、重启恢复及课程范围检索。兼容Responses路径有既有协议测试，本轮真实模型使用Chat Completions网关。

## 复现与演示

先按[长课程资料准备](course-retrieval.md)准备语料及向量索引；不需要再次下载或转写已有素材。以下命令复用该目录的资料，追加新的验收会话，不覆盖上一阶段问答报告：

```bash
# 仅比较当前混合检索与此前保存的固定结果，不调用讲解模型
uv run python examples/evaluate_feedback.py \
  --corpus data/evaluations/course-retrieval-v1 \
  --output data/evaluations/learning-feedback-demo --retrieval-only

# 真实模型连续任务，会产生API费用；--case rope可选择案例
uv run python examples/evaluate_feedback.py \
  --corpus data/evaluations/course-retrieval-v1 \
  --output data/evaluations/learning-feedback-demo
```

同一输出目录跳过已记录组。中断或修改实现后另建输出目录保留对照；不要并发写同一报告。索引故障时停止RRF对照，不把降级BM25标为向量融合。

要从网页回放这些案例，可用该语料数据目录另起本地服务：

```bash
LA_DATA_ROOT=data/evaluations/course-retrieval-v1/workspace \
  uv run uvicorn learning_agent.app:create_app --factory --host 127.0.0.1 --port 8322
```

在该网页按首条问题选会话，展开学习记录，查看四轮讲解、误解纠正及回听入口；也可使用 `http://127.0.0.1:8322/#conversation=报告中的conversation_id` 定位。新建会话亲自尝试同一问题，更能判断讲解对自己是否有帮助。原视频、数据库、完整答案和自用研究记录不随代码分发。
