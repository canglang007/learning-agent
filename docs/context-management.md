# 上下文管理：使用、限制与验收

更新于：2026-11-01 14:13:54（Asia/Shanghai，UTC+08:00）。

本文记录已实现的第一阶段预算、协议与图片管理。第二阶段的可修正学习状态、语义摘要与原话回读现已实现，见[学习状态与摘要说明](learning-state-summary.md)；第三阶段主题范围记忆也已实现，见[学习记忆说明](learning-memory.md)。总体规划见[学习状态与上下文设计](learning-context-design.md)。

## 当前行为

每次模型调用之前都会检查输入，包括执行工具后的下一次调用。系统说明、工具定义、本轮原始问题、明确反馈与最新工具批次优先保留；旧图片可移出，旧工具正文可变为位置索引，再按完整回合减少早期历史。索引只说明查过什么，不解释资料结论。

原始问题与派生学习记录分开保存。SQLite增加每轮协议档案及上下文选择快照，压缩不会删除网页消息、原始工具结果或图片文件。失败运行已取得的轨迹也归档，但不自动重放；[Agent Runtime RT1/RT2](agent-runtime.md)已支持持久提交、进度、取消与按检查点续跑；协议档案和诊断快照继续与执行检查点分工，未知主模型请求不自动重发。

图片载体的资料名、物理页码或时间标签与图像一起处理。看过的旧图像不代表本次仍有图像；需要视觉细节时Agent可重新查看，已有产物可复用。同轮恢复消耗图片与工具预算，重复无进展调用仍被阻止。恢复被移出的文字观察也受工具预算和资料版本约束。

反馈指向旧回答时，优先保留对应内容。预算不足时，仅在明确选区唯一匹配的情况下取完整段落节选；选区歧义或必要内容仍太大，会提示选中具体步骤或缩短片段，不静默猜测。原回答与提交的反馈仍保留。

## 网页与接口

发生省略的回答下会显示“本次仅使用部分历史或图像”。展开“查看本轮工具与执行状态”，可查看每一步的估算、实际usage、图片数量、移除原因和组ID。`GET /api/runs/{run_id}/context`单独返回这些诊断，不包含密钥、base64或隐藏推理内容。

旧会话首次使用时会把原协议整体保留为legacy档案；不依据图片的`user`角色猜回合。无法可靠拆分的旧协议，以已保存的用户/最终答案继续，不承诺完整重放旧中间轨迹。切换模型或协议也不会直接复用旧服务的不透明原生项目。

## 配置与边界

默认无需增加依赖：

```dotenv
LA_CONTEXT_BUDGET_TOKENS=65536
LA_CONTEXT_OUTPUT_RESERVE_TOKENS=4096
LA_CONTEXT_HEADROOM_TOKENS=4096
LA_CONTEXT_IMAGE_ALLOWANCE=4096
LA_CONTEXT_MAX_REQUEST_BYTES=67108864
LA_OUTPUT_TOKEN_FIELD=none
```

当前使用UTF-8字节量与视觉额度作工程代理估算，**不是精确token，也不是该网关窗口的验证结果**。默认可用输入代理预算为57344。详细设计曾以32768为起始实验值；默认提高到65536，以给固定工具定义、联合图片和字幕观察留出空间，真实验收仍显式使用32768触发裁减路径。

`LA_MAX_CONTEXT_IMAGES`默认跟随`LA_MAX_IMAGES_PER_TURN`，不得小于后者。图片总量和请求体积另行检查；base64只作为传输体积，不再次作为普通文本计入代理预算。视觉额度尚未校准，不能保证所有模型和图像分辨率都符合服务端限制。

`LA_OUTPUT_TOKEN_FIELD=none`表示仅预留输出。确认服务支持后，可为Chat Completions选择`max_tokens`或`max_completion_tokens`，为Responses选择`max_output_tokens`；设置字段不代表已经证明第三方服务会遵守。接口拒绝时不自动试换字段或增加远端重试。过小的本地预算也可能在模型调用前被拒绝，应依据诊断调整。

## 可重复验收

以下命令读取现有PDF并调用配置的模型，产生费用；每次使用新的输出目录：

```bash
uv run python examples/evaluate_context.py data/acceptance/optimization.pdf \
  --first-page 14 --second-page 15 --budget 32768
```

脚本不自动下载或分发课程资料，报告、完整答案、数据库和图片留在`data/evaluations/`。问题依次要求看第一页、沿用该页换例子、看第二页比较、返回第一页重新核对。不要以选择了页面冒充模型实际查阅。

本轮使用本机已有的CS231n优化课件物理第14、15页，默认兼容Chat Completions网关和`gpt-6.1-sol`：

| 项目 | 实际结果 |
| --- | --- |
| 连续问答 | 4轮完成，7次模型返回；无额外摘要模型请求 |
| 实际查阅 | 第14页 → 第15页 → 第14页；第二轮沿用已有图像换数值例子 |
| 裁减分支 | 实际触发旧图移除、工具正文转索引；每次输入最多1张图像 |
| 代理预算峰值 | 24517，低于本次可用输入代理预算24576 |
| 服务商返回usage | 输入累计35999、输出累计1792；单次输入峰值6328 |
| 用时 | 4轮合计约68.95秒，包含服务等待；不是隔离性能基准 |
| 网页 | 8条消息和2处省略提示刷新后恢复，诊断可展开；控制台无错误 |

对照原始页面图像复核：第一页只展示简单模型偏好，第二页增加灰点及噪声说明；返回第一页后，回答明确收窄跨页推论。数值例子标为假设，没有冒充图上测得的数据。这是开发过程中的内容复核，不是独立盲评或真实用户学习收益。

当轮工程回归80项通过；当前回归为189项通过、2项按条件跳过（见 README 与 CI）。新增覆盖工具循环中途预算不足、旧图缺失与同轮恢复、损坏图像错误处理、协议原生项目整组保留/移出、旧库幂等迁移、反馈节选歧义和失败归档。Responses仍未在当前真实网关验收，保持离线协议验证的边界。
