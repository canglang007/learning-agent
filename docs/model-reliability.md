# 模型服务适配与可靠性

更新于：2026-10-21 06:18（Asia/Shanghai，UTC+08:00）。

当前实现包含三个层次：`model_registry.py` 根据协议、模型名和配置生成保守的文本/视觉/工具调用能力矩阵；Provider 对明确的临时 HTTP 状态（408、409、425、429 和 5xx）进行一次短退避重试；Runtime 继续负责未知结果的幂等暂停和人工确认，不会自动重发未知请求。

网页 `/api/status` 会显示当前模型的能力。视觉任务只能使用登记为视觉模型的配置；未知模型不会被乐观地标记为支持视觉。模型能力信息用于提示和路由前置检查，不能替代真实回答评测。

可靠性记录沿用 Runtime 的操作记录：每次模型操作保存 purpose、attempt、状态、耗时、usage 和错误类型。后续可以在评测报告中按 provider、模型、错误类型比较完成率和降级路径。

目前仍需通过真实网关分别验证不同服务商的工具调用、视觉输入和流式协议；兼容网关的协议差异不能只由模型名称推断。
