# 检索：BM25 → 混合 → 精排

更新于：2026-11-24。这份文档写**当前**的检索方案：为什么是这三段、今天的指标是多少、
哪里还没做好。

**本文件不写历史数字。** 想查"以前是多少、为什么改"，看[检索口径沿革](retrieval-history.md)。

**报数字必须带模型名。** 本文所有指标的向量是 `bge-m3`（1024 维，ollama），
精排是 `BAAI/bge-reranker-v2-m3-int8`（0.57 GB）。换任何一个，数字都不再是这个数。

## 一句话结论

v5 语料（7 讲 11 份材料、942 块、92 题中 83 道可评分）上，产品路径（`Retriever.search`，
depth=5、每页 ≤2 条）的 Hit@5：

**BM25 0.40 → 混合 0.639 → 加精排 0.807**（MRR@5 0.341 → 0.464 → 0.682）。

分模态是 pdf 0.524 → 0.714 → **0.857**、video 0.361 → 0.623 → **0.787**。
视频从 0.36 到 0.79 是这套系统最大的一段跨度，也是混合检索真正不可替代的地方——
中文提问、英文字幕，BM25 在这类题上几乎全空。

83 道可评分题里还剩 16 道不中：跨讲对照 4 道全灭、英文三讲 7 道、
讲义 PDF 3 道、第一讲视频 2 道。原因三类：转写质量、标注粒度、分块切断，逐条见
[多模态评测](multimodal-eval.md#按材料)。

## 为什么 BM25 不够

BM25 走字面匹配。中文按 bigram 切（无空格语言的标准做法），英文按词切。
问题出在**跨语言**：讲义是英文，提问是中文。

```
问：为什么正则化偏好简单模型？
BM25 命中：一份中文讲座的视频块（无关）  ← 中文 bigram 在英文讲义里没有对应词
```

```
问：CS336归一化放在子层之前，为何不影响残差直通？
BM25 命中：空                          ← 全空，向量是唯一出路
```

这不是调参能修的：查询里根本没有出现在文档中的词。

## 三段设计：每一段补上一段坏在哪

### 第一段 BM25：字面

词面重叠就是全部信号。对公式编号、API 名、术语缩写这类"必须字面对上"的查询最可靠，
对"用自己的话问"完全无能。

### 第二段 多语言向量 + RRF：语义

双塔模型把查询和文档各自编码成向量，再比余弦。语义相近就能找回，跨语言问题解决一部分。

两路怎么合：**RRF，不做加权**。BM25 分数无上界、余弦在 [-1, 1]，量纲不同且没有可靠标定，
加权等于拍脑袋；RRF 只用排名（`Σ 1/(60 + rank)`），稳健。

RRF 的毛病是**它只看"排第几"，把"这个结果有多确定"扔了**。BM25 第一名可能是第二名的十倍，
也可能只高一点点，RRF 一律当"第一名"处理；向量那一路的相似度也没被用上。

### 第三段 交叉编码器精排：逐对读原文

精排把"查询 + 候选"拼在一起送进模型，直接给一个相关性分数——它能读懂改写，
所以补上了双塔拉不齐的跨语言对齐。它慢得多，只能对前几十个候选做，不能用来找候选。

**把 CE 分数直接替换原排序会让部分题变差**：CE 对"用自己的话问"很敏感，但对必须字面对上的
场景（公式编号、API 名、术语缩写）会把 BM25 本来找对的答案压低，因为它觉得"意思上不相关"。
在名次上再融一次（CE 新名次与原名次做 RRF）也不行——RRF 又丢一次分数，把 CE 唯一优势抹掉。

所以改成**分数空间融合**：

```
score = 0.9 · sigmoid(CE 分数) + 0.1 · 归一化后的 RRF 分数
```

CE 占九成，RRF 留一成做托底。直觉是：CE 判断更准，但会漏字面对得上的情况；RRF 范围广，
但不够准。让 CE 主导，只在 CE 把某个候选压得很低时，让 RRF 把它拉回来一点。

融合权重 0.9 是在小语料上选的，后来在大样本上复核过：最优区间移到 0.75–0.85，
但 0.9 只差一条题。**没有改默认值**——那等于用报分用的同一套题去拟合参数，
报出来的数字立刻失去意义。这条敏感性如实记在[沿革](retrieval-history.md)里，
默认值留待独立验证集再定。

## 当前指标

### 总表（v5：7 讲 942 块，83 道可评分）

| 模态 | 题数 | BM25 | 混合 | 混合 + 精排 |
|---|---|---|---|---|
| pdf | 21 | 0.524 | 0.714 | **0.857** |
| video | 61 | 0.361 | 0.623 | **0.787** |
| text | 1 | 0.00 | 0.00 | **1.00** |
| image | 1 | 不计分 | 不计分 | 不计分 |
| **合计** | **83** | **0.40** | **0.639** | **0.807** |

`text` 那 1 题的材料是合成笔记（2 块，开头自述"含故意写错的声明"，供不可信材料用例），
说明不了文本检索水平，**不要把它当成"文本能力已覆盖"**。

`image` 那题是纯图页（文字层为空、0 分块），标了 `unretrievable` 单列不进分母——
拿文字检索去命中纯图页是不可能的事。

精排那一列是**产品路径**跑出来的（depth=5），不是拿更深的候选池截前 5。两者差 1–2 题：
下面的消融用 depth=40 的候选池，基线是 0.631。

### 消融：三条被数据否定的改法

`scripts/retrieval_ablation.py`，候选深度 40、向量 `bge-m3`、精排 `v2-m3-int8`：

| 配置 | 总 Hit@5 | MRR@5 | any Hit@5 | 跨讲 all |
|---|---|---|---|---|
| 混合（基线） | 0.631 | 0.459 | 0.662 | 0/4 |
| 每材料最多 3 条 | 0.583 | 0.447 | 0.613 | 0/4 |
| 子查询融合 | 0.595 | 0.424 | 0.625 | 0/4 |
| **混合 + 精排** | **0.798** | **0.674** | **0.838** | 0/4 |
| 子查询融合 + 精排 | 0.786 | 0.671 | 0.825 | 0/4 |
| 仅 BM25 + 精排 | 0.548 | 0.473 | 0.575 | 0/4 |

- **限制同材料候选条数让指标下降**（−4.8pt）："同讲霸榜"不是跨讲题失败的原因。
  "前 5 被单一材料占满"的题从 26 道降到 0，跨讲仍 0/4——占了位置并不是原因。
- **复合查询拆成子查询再融合，单独用掉 3.6pt**，叠上精排反而比纯精排低 1.2pt——
  缺的证据没被找回来，还引入了噪音。逐子查询查过：连「KV cache 剪枝」都召不回原文写着
  "KV Cache 的 pruning" 的那块（`scripts/inspect_subquery.py`）。
- **精排只接 BM25 候选时是 0.548**：说明精排不能替代向量召回，两者各管一段。

这三条留在脚本里（`--quota` 可复现），不是为了展示"试过多少种"，是防止以后有人当新想法重来。

## 跨讲题：如实记 0/4

`targets_mode=all` 的 4 道题要求**两份证据同时进前 5**。它们在所有配置下都是 0/4：
扩候选池、分材料召回、换双塔、改分块、换精排都没有改变结果。

结论不是"还没调对参数"，而是**这 4 道题的目标块与"最像答案的块"不是同一个块**：
精排偏爱同材料里直接回答问句的概括句，而标注区间选的是具体讲解块。
逐目标名次、权重扫描、8 份证据的原文对照，全部写在[跨材料检索](cross-material-retrieval-plan.md)。

## 实现要点

- **双通道 + RRF 融合**，不做加权（理由见上）。
- **索引与查询分离**：chunk 向量持久化在 `chunk_vectors`，`encoder` 字段是
  `["local", 模型名]` 的指纹。换模型/换地址自动失效并重建，不会混用两套向量。
- **精排只重排、不改召回集合**：只对融合后的前 `LA_RERANK_CANDIDATES`（默认 20）个候选逐对推理。
  砍到 10 会掉 4.8pt，延迟不能从候选数省。
- **降级必须说出来**：向量不可用时返回 `retrieval="bm25"` 且 `dense_status`
  给出原因（`disabled` / `index_incomplete` / `embedding_request_failed:*`）；
  精排失败给 `rerank_status=rerank_failed:*`，不冒充重排发生过。
- **同页去重**：每页最多 2 条命中，避免 5 条结果全来自同一页。
  没有再加"同材料配额"——实测它降低指标（见上）。
- **BM25 统计按语料缓存**：`Bm25Index` 把分词统计与查询打分分开，`Retriever` 按块集合
  签名缓存、语料变化自动重建。原先每次 `search` 都重新分词，942 块时单次白花 1–2 秒；
  分数公式与旧实现逐项相同（有回归测试守着）。
- **中文分词**：bigram 滑窗（`归一化` → `归一`/`一化`），不引分词器依赖。

## 向量来源：ollama 默认，进程内 ONNX 是回退

三条路都试过，现在默认走 ollama：

| 来源 | 状态 | 说明 |
|---|---|---|
| **ollama + `bge-m3`** | **默认** | 模型常驻在 ollama 进程里，不占应用进程内存；本机一条 `ollama serve` 即可 |
| 进程内 ONNX（`fastembed`） | 可选回退 | 无外部服务、无网络依赖，适合装不了 ollama 的环境；`LA_EMBEDDING_PROVIDER=local` |
| 云端 API | 不可用 | 当前网关只代理 LLM，`/embeddings` 直接 404（实测 `model_not_found`） |

**回退口径要标清楚**：进程内 ONNX 用的是 384 维 `paraphrase-multilingual-MiniLM-L12-v2`，
同一套题上混合检索比 bge-m3 低 8.5 个点（跨语言术语对齐补不上：中文问「剪枝」要命中
英文讲稿里的 "pruning"）。中英混排的语料上，这个差距不是调参能补的。

进程内 ONNX 那条路的资源实测（Azure 1 vCPU / 836 MB，MiniLM-L12、`LA_EMBEDDING_THREADS=2`）：

| 指标 | 数值 |
|---|---|
| 模型加载（首次含下载） | 121 s |
| 索引 208 个 chunk | 16.9 s |
| 单条查询编码 | 0.08 s |
| 进程 RSS / 峰值 | 495 MB / 505 MB |

**没有对 ONNX 权重做 int8 二次量化**：fastembed 给的是 fp16，onnxruntime 的
`quantize_dynamic` 不接受 fp16 输入，强行转 fp32 再量化会多一层数值改写。
按"省计算只能来自算法本身"的原则，这一步没做。

## 复现方式

```bash
uv sync --extra embed --extra asr
export LA_EMBEDDING_CACHE_DIR=~/.cache/la-models   # 固定缓存，避免重复下载

# 1) 建整讲语料（7 讲约 18 分钟，绝大部分花在 ASR；可续跑）
uv run python scripts/build_lecture_corpus.py

# 2) 先校验标注可达，再跑指标
uv run python scripts/check_annotation_targets.py --queries evals/retrieval-v5.json
uv run python scripts/retrieval_report.py \
    --corpus data/evaluations/multimodal-v1/corpus/workspace.db \
    --queries evals/retrieval-v5.json \
    --json data/evaluations/multimodal-v1/report.json
```

输出包含总体指标、分模态指标和逐题排名。`--model` 换向量模型做同样对照，
`--rerank-model` 换精排，`--rerank-candidates` 改候选数；三者的当前值都已写进 JSON 的
`provider` / `embedding_model` / `rerank_model` / `rerank_candidates`，两档数字不会串口径。

重排对照（走产品 `search` 路径，首次含模型下载 0.57 GB）：

```bash
uv run python scripts/rerank_experiment.py        # RRF vs 精排
uv run python scripts/rerank_fusion_experiment.py # RRF vs 纯替换 vs 分数融合
uv run python scripts/rerank_alpha_sweep.py       # 融合权重扫描
```

这几个脚本的模型默认值都来自配置（`scripts/eval_assets.default_rerank_model()`），
不再各自写死；复现历史数字要显式传 `--rerank-model`。

## 已知局限

- 83 道可评分题，"0.807 与 0.82"这种差距仍没有统计意义；能站住的结论是
  "向量通道有用、精排有用、视频上最有用"。
- 同一事实在讲义与讲稿里重复出现，页级单一标注偏严（逐条复核见[沿革](retrieval-history.md)）；
  多目标标注未做。
- 分块按固定字数与时间切，会把定义句切在边界上，含后半句的分块语义残缺。
- 英文三讲走本地 ASR，没有断句和术语修正（"flotswaget" 应是 FLOPs），
  转写质量是这几讲的上限。
- 只覆盖中↔英与中↔中；未测日韩、公式主导的页面。
- 视频按时间段召回，标注粒度到秒级但分块仍是 40–45 秒，比页级更粗。
- 跨材料对照做不到（4 道全灭），这是已知能力缺口，不是待修 bug。
