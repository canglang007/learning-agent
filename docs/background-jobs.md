# 本地持久后台任务

当前实现覆盖回放准备、音频转写和语义索引。任务与成功结果保存在SQLite，预览放在`data/jobs/{job_id}/`。API不再使用BackgroundTasks执行这些操作，启动API也不会重置正在处理的任务。

## 启动与日常操作

在相同项目目录、相同环境配置下分别运行：

```bash
uv run uvicorn learning_agent.app:create_app --factory --host 127.0.0.1 --port 8320
uv run python -m learning_agent.worker
```

两条命令各占一个终端。默认数据目录为`data/`，可用`LA_DATA_ROOT`设置；两个进程必须一致。处理进程目前支持macOS/Linux，通过文件锁限制同一数据目录只有一个处理进程。`--drain`处理完当前队列即退出，供验收脚本使用。

网页的“后台处理任务”展示排队、处理中、暂停、失败、取消和完成。处理进程离线时显示启动指引，任务不会丢失。在线状态依据周期心跳，异常退出后最多约10秒才显示离线。

- **暂停**：暂停排队中的指定任务；运行中ASR在当前分片结果保存后暂停，转码在整个转码步骤结束后暂停，不承诺立即停止任意编码帧。其他未暂停的任务仍可执行。
- **继续**：重新排队暂停任务，复用已保存成果。
- **重试**：明确重新执行失败任务；遇到`remote_result_unknown`会提示可能再次计费。
- **取消**：立即撤销发布资格，正在进行的计算或请求可能仍需结束，不保证退回云端费用。

修改模型、服务或处理方案不会让旧任务静默切换配置。当前进程配置与任务快照不符时暂停；可恢复原配置后继续，或重新点击处理入口创建新任务。任务快照不保存API key，同一模型/接口下旋转密钥可以继续。

## 当前恢复粒度

| 类型 | 当前承诺 | 尚未实现 |
|---|---|---|
| 回放准备 | 支持的H.264/AAC MP4或AAC M4A直接回放原文件；其他格式临时转码、校验后原子发布；中断可采用完成产物 | 任意编码位置续转；实时编码进度 |
| 转写 | 只解码当前窗口，逐片保存原始时间与结果；中断复用成功片段，完成后合并/发布，旧字幕期间可用 | 词级精确对齐；自动修正识别文字 |
| 语义索引 | 每批向量与完成记录一起提交，继续时跳过已保存向量 | 多工作进程调度、分布式执行 |

本地任务运行中被终止，处理进程重启后重新排队未完成步骤。普通处理错误保留失败状态，由用户重试；不会无限自动重试。

兼容云端ASR或向量请求开始后，如果结果尚未持久保存，异常退出会标记`remote_result_unknown`，不自动重发。ASR逐片确认，用户重试时跳过已保存片段，只重做未保存片段；远端结果不明的片段仍可能再次计费。该标记不能证明云端实际计费。

正常Ctrl-C/SIGTERM退出会回收受管媒体子进程。SIGKILL无法执行清理，媒体子进程继承目录锁；它退出前不能启动第二个处理进程，避免同时写同一临时文件。此时启动失败提示可能有尚未退出的媒体子进程，待其结束后重新启动。半成品不会成为可播放资料。

当前支持默认2 GiB/4小时的媒体，分块落盘与分片ASR已实现，见[完整课程验收](long-course-acceptance.md)。上传完成会等待媒体探测与登记，探测在工作线程中执行；重试完成请求可接续固定资料ID的登记，不重复上传或创建资料。回放、字幕和索引依然独立准备。

## 字幕与索引的一致性

转写先保存候选结果，再在一个事务内更新活动字幕、资料版本、旧索引失效和任务完成状态。字幕版本保存在`transcript_revisions`，旧字幕在新转写完成前不会被删除。

用户随时可以上传有效SRT/VTT，原子替换字幕并取消旧转写候选；旧任务即使稍后返回也无法覆盖。索引批次保存时核对实际存在的资料段落，任务完成时再次检查输入版本，旧版本不能标成当前资料索引成功。

旧版本ready媒体、字幕、会话及引用保持可用。旧processing媒体若没有持久任务，处理进程会创建回放任务；旧本地ASR从头开始，旧云端ASR明确等待重试，不猜测已消失的临时转写成果。

## 任务接口

| 接口 | 用途 |
|---|---|
| `GET /api/spaces/{space}/jobs` | 返回该空间最近50个任务和处理进程在线状态 |
| `GET /api/jobs/{id}` | 查看任务、阶段、尝试次数和已保存进度 |
| `POST /api/jobs/{id}/pause` | 请求暂停 |
| `POST /api/jobs/{id}/resume` | 继续已暂停任务 |
| `POST /api/jobs/{id}/retry` | 明确重试失败任务 |
| `POST /api/jobs/{id}/cancel` | 取消任务发布 |

原有媒体上传、`prepare`、`transcribe`和空间`retrieval`入口创建同一队列的任务。重复提交相同活动任务会返回原任务；明确重试相同输入/配置的失败任务也复用原记录及成功成果。没有配置ASR/向量时，相应执行入口返回503，字幕上传与关键词检索仍可用。

媒体上传使用`POST /api/spaces/{space}/uploads`创建会话，`PATCH /api/uploads/{id}`携带`Upload-Offset`逐块接收，`GET`查询确认偏移，`POST /complete`收录，`DELETE`取消未收录副本。每块最多8 MiB，服务端按实际字节检查上限；不持有数据库事务等待网络。文件同步落盘后才更新确认偏移，断线未确认尾部在下一次接收前丢弃。旧multipart入口仍兼容，内部按块处理；浏览器使用新协议才能暂停和刷新续传。

## 已验证与证据边界

工程测试覆盖并发提交去重、API重启不误伤任务、重复处理进程拒绝启动、真实子进程在预览发布前崩溃后的产物采用、半成品不开放回放、ASR完整结果复用、索引批次复用、新字幕覆盖竞争和过期索引取消。另验证强制终止后媒体子进程仍持锁。

这些测试验证工程恢复和一致性；ASR内容正确性、整课资源占用及真人学习收益仍需分别验收，不由模拟模型测试推定。
