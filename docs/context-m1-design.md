## 1. 用户可观察到的变化

对话历史变长时，优先移出较早、无关的工具细节和旧图片，继续回答当前问题；旧记录仍可在网页回看。界面在确实裁减历史时提示“本次仅使用部分历史，可指定早期回答继续讨论”，不宣称模型仍记得全部内容。M2实现前，早期历史的精确接续能力有限。

回答仍由Agent自主选择行动。上下文管理器负责提供合法、可用的模型输入；超出必要内容预算时明确提示收窄问题，不把预算不足包装成资料不存在或用户理解有误。

## 2. 对象与所有权

采用Python数据类或严格Pydantic模型，不要求引入新的编排框架。下列为拟定字段，不是已有实现：

| 对象 | 核心字段 | 作用 |
| --- | --- | --- |
| `TurnInput` | `run_id, question, feedback, focus, learning_context` | 原始问题与派生上下文分开；本轮输入不含旧注入包 |
| `ProtocolGroup` | `id, turn_seq, step, kind, messages, call_ids, assets, status` | 描述可整体选择的协议单位；`kind`区分输入、工具批次、最终回答、失败状态和legacy块 |
| `AssetRef` | `asset_path, material_id, location, revision, label, observation_id` | 图片及来源标签；模型请求编码前不读入base64 |
| `ModelProfile` | `protocol, model, service_id, C, O, H, image_allowance, estimator_version, output_capability` | 模型预算和已验证能力；`service_id`不含凭据 |
| `PreparedContext` | `messages, selected_groups, render_modes, omissions, assets, revision` | 派生输入视图，保留到原始组的映射；不能修改原始轨迹 |
| `ModelRequest` | `endpoint, payload, estimate, profile_id` | 实际准备发送的协议体；凭据由发送器临时加入请求头 |
| `BudgetEstimate` | `text_units, image_units, opaque_units, input_total, request_bytes, uncertainty` | 工程估算及不确定性，不冒充服务商精确token |

`run_turn`持有本轮完整轨迹，`ContextManager`持有选择结果，`Provider`持有序列化与发送逻辑，`Store`负责事务归档。当前模型步的指令与工具定义必须作为预算输入，不能在估算后临时追加未计入的长说明。

### 协议分组规则

- 新回合的用户原话与反馈分别保存；图片载体虽然是`role=user`，明确标记为`attachment`，不产生新回合。
- 一个助手工具批次包含助手消息、全部`tool_call_id`对应结果，以及随后带标签的图像载体。多个调用必须都取得结果；无效参数和预算拒绝也返回对应错误结果。
- 一个组未收齐结果时不得供模型继续调用，也不得将缺失结果的轨迹冒充可重放历史。
- 纯文本最终答案独立记录；`deliver_explanation`的最终正文在UI消息中保存，协议档案仍保留实际终止工具批次。后续上下文可显式加入“上一轮已交付答案”的派生文本，不伪造当时存在的助手消息。
- 分组依据运行器记录的边界和ID，不根据正文里是否出现某个标签猜测。原始工具参数与结果保持原样，截取只能发生在显式派生节选中。

## 3. 每次模型调用前的流程

```text
收集本轮问题、反馈目标、工作记录和完整协议组
  → 确定必要组及候选旧历史，先按图片上限选择资产
  → 构建协议请求表示并估算系统说明、工具定义和全部内容
  → 若超预算，按固定顺序减少可选内容，再估算
  → 检查调用/结果配对、图片标签、总请求体积与必要项完整性
  → 只编码选中资产，得到最终请求并复核体积
  → 保存上下文选择快照，发送一次模型请求
  → 关联usage/失败结果；将新返回消息加入完整轨迹
```

调整仅为本地确定性操作，不触发模型。每步按有限候选列表推进，同一候选不反复尝试；所有删减尝试也计入原有运行总时限。最终请求估算不通过则不发送。

`Provider`拆为`build_request / estimate / send / parse_response`；可保留现有`step`作短期适配入口，但生产Agent不应通过它绕过ContextManager。`Scripted`测试模型通过统一的调用适配层接收已选消息，无需假装提供HTTP序列化能力；序列化预算由独立协议构建器测试。

## 4. 保留与降级算法

### 必要内容

固定系统说明与可用工具定义、本轮原始问题、有效明确反馈、反馈所指步骤、最近一次工具观察及当前仍需判断的图片必须保留。学习记录保留当前卡点、讲法与反馈，不重复注入旧记录包。

“必要”不能由模型自行给任意旧内容打标。执行器依据本轮输入、反馈目标ID、刚执行的批次确定；用户选中位置提供相关性，不等于已查阅。当前工具批次若过大，不会通过截断JSON强行发送。

### 可选历史的处理顺序

1. 先去掉历史中已经过期、重复的派生注入；同一次实际工具调用不重复加入。
2. 旧图片按本轮所选位置、反馈目标关联、最近查看顺序保留；超过图片上限先使用合法的无图变体。
3. 较早已完成工具组不再重放全部正文，改为有来源ID的确定性索引：查过什么、何种模态、位置与是否成功。索引不包含猜测出的资料结论；精确内容仍需重新读取。
4. 近期保留完整用户/答案回合，逐个移出较早完整回合；最早保留处加明确的历史省略提示。小型旧历史索引也占预算，可继续减少。
5. 历史反馈目标若正文太长，按明确`focus_text`匹配并取完整段落节选，注明上下文省略。没有明确选区、匹配重复且歧义或节选仍太大时，不猜测目标步骤。

每次选择保持原有相对顺序；预算容许时无需预先删减。步骤3是可追溯索引，不是语义摘要，不能提前宣称实现M2。被省略的原话在M1网页中仍可查看，Agent读取被压缩原话的工具在M2补充。

### 失败分类

| 条件 | 行为 |
| --- | --- |
| 问题、系统说明或当前必要观察已超过预算 | 不调用模型；保存`context_required_too_large`与可读提示，建议缩小资料片段或问题范围 |
| 无法确定旧回答的反馈选区 | 保留能合法容纳的回答；容纳不了时提示选择具体步骤，不裁切到含义不明 |
| 本轮刚返回的图片损坏/不可读 | 不谎称已看图；保留错误观察，允许在剩余步骤内重新检查或明确资料不足 |
| 无关的旧图像资产缺失 | 移除图像载体并记录原因；保留历史位置与失败提示，不使整轮问答直接失败 |
| 协议组缺失结果、ID冲突 | 本地协议错误，不发送请求；保留诊断和原始档案供排查 |
| 网关拒绝上下文大小/不支持输出限制字段 | 按现有脱敏错误路径结束并记录配置标识，不自动追加远端重试或猜测另一协议 |

失败仍写入用户消息、明确反馈和失败状态；学习笔记不更新。失败运行内已经发生的模型/工具组需要归档，但标记不可自动重放；下一轮沿用上次成功上下文，加上此次问题与失败提示。

## 5. 图片与Responses的安全变体

普通工具组允许两种渲染：`full`保留全部选定图像；`without_old_images`保留原助手调用及全部结果，移除应用添加的旧图像载体，补充“历史看过，本次未附图”的位置标签。原始观察里的图片路径只是产物指针，不能被描述为当前已发送的图片。

这个变体不修改原始工具结果，不改变调用ID，也不拆开调用/结果配对。Responses的原生`provider_items`整块保持不变；如果图像或其他必要内容本身嵌在原生项目内，不能局部改写，只能保留或移出整个已完成组。移出后替代文本不得继续携带旧`provider_items`。

同一位置因当前问题需要再次看图，允许复用已有产物重新附加。去重状态区分`tool_fingerprint`与`currently_attached_asset_ids`；同轮只有确实从输入移出且观察版本未过期时，才允许相同指纹恢复附件，不重复执行解码/渲染。恢复后再次请求相同内容仍返回重复调用提示。每次重新附加计入本轮图片次数与工具调用预算，不开启无限恢复循环。

默认`max_context_images`与现有`max_images_per_turn`一致；配置时前者不得小于后者，保证一个合法当前批次能进入下一步。两者都不是视觉token保证。对旧图片的移除按资产标识和标签处理，不能只保留图片却移除其时间/页码说明。

切换协议、服务或模型时，不复用原服务的不透明原生项目。M1把历史转换为可见用户/最终答案与实际工具索引，不伪造跨协议工具调用链；当前运行中禁止切换配置，下一轮重新构建输入。原始档案继续保存原协议版本。

## 6. 配置与估算边界

新增设置均为拟定值，需在实现验收时校准：

| 设置 | 起始值 | 约束 |
| --- | --- | --- |
| `LA_CONTEXT_BUDGET_TOKENS` | 32768 | 本地工程总预算`C`，不是网关窗口声明 |
| `LA_CONTEXT_OUTPUT_RESERVE_TOKENS` | 4096 | 输出预留`O`；未验证输出限制能力时只预留，不宣称已强制 |
| `LA_CONTEXT_HEADROOM_TOKENS` | 4096 | 误差预留`H`；须满足`C > O + H` |
| `LA_MAX_CONTEXT_IMAGES` | 派生自每轮图片上限 | 1–6张，且不小于本轮新增上限 |
| `LA_CONTEXT_MAX_REQUEST_BYTES` | 64 MiB | JSON请求体上限，与token预算独立；仍保留现有单张6 MB限制 |

估算器v0以UTF-8字节量、封装余量及单独的视觉额度产生保守工程代理量；记录策略版本与未知项，不声称是数学上界。视觉额度放在模型能力档而非伪装成所有服务通用常数。图像尺寸和原生项目的计费未知时标记`uncertainty`；真实usage累计用于复核配置，不能以一次调用证明所有输入都安全。

初始实验档可按每张4096代理单位预留视觉额度，并标记未校准；这是待验证的本地预算参数，不是该网关真实计费规格。不透明项目用序列化字节量单独估算，不能遗漏，也不能据此声称得到了隐藏推理token数。协议构建器在编码图片前生成请求计划，估算文字与工具时使用同一协议结构；编码后复核最终JSON体积，避免把base64字符作为普通文字重复计入token代理量。

配置能力档只允许受支持的输出限制字段与已确认协议组合，不提供任意请求字段透传。HTTP错误不能自动决定切换字段。数据目录里的能力档与API key分离；快照记录配置ID，不复制凭据或可能带token的完整URL。

## 7. 归档与迁移

M1新增`protocol_turns`与`context_snapshots`。拟定最小字段：

```text
protocol_turns:
  conversation_id, turn_seq, run_id(unique), schema_version, profile_id,
  raw_input_json, groups_json, replay_status, created_at
  unique(conversation_id, turn_seq)

context_snapshots:
  run_id, step, schema_version, profile_id, selection_json, estimate_json,
  result_json, created_at
  unique(run_id, step)
```

时间使用带时区的UTC时间持久化，网页按本机时区显示；文档时间仍明确标注时区。`selection_json`仅保存选择的组ID、模式、来源和省略原因，`result_json`为脱敏状态/usage，不保存密钥、base64或模型内部推理。

`finish_run`同事务保存原始新增组、答案、既有学习笔记与运行状态；序号在事务中分配，不依赖按角色数消息。不可重放的失败组不进入后续自动选择。`conversations.protocol`作为过渡缓存，标记格式版本并可从归档重建；不能把经过选择的模型输入覆盖为唯一历史。

旧会话首次访问时幂等迁移：旧协议整体保存为legacy块并记录已迁移状态；验证过的组可以索引，无法识别的部分不强拆。旧会话的可见用户/答案、反馈、笔记和工具事件仍可用于有来源的输入节选；含糊的旧注入按派生内容处理，不能当成新的用户偏好。迁移过程不调用模型、不新建学习画像；原始完整数据保留。

legacy档案使用`turn_seq=0, run_id=NULL`，不能把整段旧历史假绑到某个运行；新回合从1递增。迁移以会话内唯一legacy记录幂等识别，读取与新增回合遵守现有同会话运行互斥；迁移与归档操作仍在SQLite事务内完成。

这两张表在M1不承担恢复执行功能。模型调用前的快照没有执行结果，进程崩溃也可能留下待完成记录；不能据它自动重发可能已计费的请求。

## 8. 改动位置与完成标准

按依赖顺序实施：

1. `context.py`定义协议组、选择策略和诊断；`provider.py`提取可测试的请求构建/估算，不改教学决策。
2. `store.py`加入幂等迁移与每轮归档，保留失败观察、现有消息与反馈；禁止派生输入覆盖唯一原始历史。
3. `agent.py`每次模型调用前准备上下文，调整图片重新附加与去重，沿用现有步骤/调用/时间预算。
4. `app.py`与网页工具详情增加上下文省略提示及诊断接口；`.env.example`与用户说明标明估算边界。

必要验证覆盖：工具循环中途超预算、多工具配对、终止交付正文、旧回答反馈、无关旧图缺失、当前图片不能被立即移出、旧图恢复且不死循环、Responses不透明项目保持或整组移除、协议切换、旧库重复迁移、失败档案保留。沿用既有反馈/PDF/媒体回归，不写镜像实现的测试充数。

真实验收使用现有课程资料，至少一段连续追问和一次图表跨轮回访；记录每步估算、真实usage、实际图片数、远端请求次数与延迟。若未触发预算或图片移除，不能写“长上下文路径已验收”；离线可控预算用例验证裁减分支，真实行为与工程测试分开报告。Responses在当前网关未真实验证，仍只能声明离线协议通过。

完成M1的标准是输入逐步受控、协议合法、原始数据保留、失败可解释且当前学习闭环无回归；随后进入M2，不把M1当成完整学习记忆模块。
