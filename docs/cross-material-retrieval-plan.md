# 跨材料检索：四条路径逐条实测（结论）

更新于 2026-11-24。这份文档记一次专项调查：**跨讲对照 4 道题为什么一道都过不了，
四条可能的解法各自值不值。** 结论是 **0/4 没能救回来**，但过程中查清了三件事：
失败究竟在哪一层、哪条路是死路、以及一个顺带发现的真实收益（精排换代，已采纳）。

所有数字同一套口径：v5 的 92 题（83 题可评分）、7 讲 11 份材料 942 块、
向量 `bge-m3`（ollama）、精排 `bge-reranker-v2-m3-int8`、
产品 `Retriever.search` 口径（depth=5、每页≤2 条）。
`*` 标记的数字来自离线脚本，不走产品路径，只用来定位原因。

## 一、结论表

当前口径：v5 的 92 题（83 题可评分）、7 讲 11 份材料 942 块、向量 `bge-m3`、
精排 `bge-reranker-v2-m3-int8`，产品 `Retriever.search`（depth=5、每页≤2 条），
全量 Hit@5 **0.807**。下表只列各配置对跨讲题的实测结果：

| 配置 | 跨讲 all（4 题） | 判定 |
|---|---|---|
| ① 全局混合 + 精排（现产品口径） | **0/4** | 基线 |
| ② 分面召回：每材料前 30 条合并成一个池再整池精排 * | **0/4** | 无效 |
| ③ 分面 + 子问句逐材料精排 + 交错合并 * | **1/4** | 只值 1 题（旧精排下；换精排后见 ⑧） |
| ④ 换双塔：`qwen3-embedding:0.6b`（1024 维）* | **0/4** | 无效 |
| ⑤ 相邻块重叠（每块拼上下一块再精排）* | **0/4** | 净负 |
| ⑥ 问句转繁体（简繁失配假设）* | **0/4** | 假设不成立 |
| ⑦ 精排全精度 `v2-m3` | **0/4** | 对本题无效 |
| ⑧ 现精排 + 子问句 + 交错合并 * | **0/4** | 无效（换精排前是 1/4） |

跨讲题在**所有**配置下都过不去，而单材料题在换精排后明显变好。这个反差本身就是结论：
**这 4 道题的失败不是"还没调对参数"，是它们的目标块与"最像答案的块"不是同一个块。**

## 二、失败到底在哪一层

### 2.1 先排除"召回池"：进池早就够了

先确认"证据在不在池里"（`scripts/inspect_facet_recall.py`）：
k=30 时 8 份证据有 7 份进池，只有 hy_flash 那份（材料内第 67/69）不进。**池里有证据，前 5 仍然没有**。

### 2.2 决策者是精排：权重怎么调都不行

分面池上把融合权重从 0 扫到 0.9，没有一档能同时容下两份证据：

| 权重 | cross_serve_cost | cross_flash_kv | cross_long_context | cross_kv_reduce |
|---|---|---|---|---|
| 0.0（纯 RRF） | ✗ [7, 144] | ✗ [—, 209] | ✗ [34, 92] | ✗ [110, 252] |
| 0.3 | ✗ [1, 145] | ✗ [—, 210] | ✗ [35, 83] | ✗ [44, 183] |
| 0.5 | ✗ [1, 145] | ✗ [—, 212] | ✗ [35, 70] | ✗ [13, 135] |
| 0.7 | ✗ [1, 145] | ✗ [—, 214] | ✗ [36, 53] | ✗ [7, 79] |
| 0.9 | ✗ [1, 146] | ✗ [—, 208] | ✗ [35, **15**] | ✗ [7, **40**] |

（括号里是两份证据在合并结果里的名次；"—" 表示该块根本没进分面池。）

权重从 0 拉到 0.9 确实能救回**其中一份**：长上下文那题的第二份证据从 92 名升到 15 名、
剪枝那题从 252 升到 40。但另一份卡死在 34–36 名（cs4）、`hy_flash` 则始终没进池。
**每道题都有一份证据是权重救不动的**，所以没有一档能同时容下两份。

### 2.3 关键指标：目标块在它自己材料里的名次

只在该材料内部排序，不看别的材料（`scripts/inspect_ce_neighbors.py`）：

| 题目 | 证据（材料块数） | 材料内 RRF | 材料内精排 | 接子问句后精排 |
|---|---|---|---|---|
| cross_serve_cost | cs9（108） | **1** | **1** | **2** |
| | cs10（123） | 16 | 42 | **9** |
| cross_flash_kv | hy_flash（69） | 67（未进前 30） | 62 | 61 |
| | hy_kv（53） | 23 | 25 | 32 |
| cross_long_context | cs4（122） | **4** | **1** | **1** |
| | hy_kv（53） | 10 | **5** | **6** |
| cross_kv_reduce | hy_kv（53） | 12 | **5** | **2** |
| | cs10（123） | 28 | 18 | 8 |

"接子问句"指：一道题问两件事，却拿整句去和只讲一件事的块逐对打分，精排会偏爱关键词
覆盖多的块。按材料换成各自的子问句（"Flash Attention 省的是哪一类开销" /
"KV cache 省的是哪一类开销"）再打分，两份证据的名次明显分化：
cs10（服务成本那题）42 → **9**、cs10（剪枝那题）18 → **8**、hy_kv（剪枝）5 → **2**，
而 hy_kv（Flash/KV 那题）25 → 32、hy_flash 62 → 61 反而更差。
**机制是真的，但不普遍**：它救的是"问句里两件事各占一半"的题，
对"目标块通篇没出现关键词"的题无效。按门控取前 3 后，仍有 9/32/61/8 够不到前 5。

### 2.4 为什么够不到：前 5 只够分给每份材料 3 条

交错合并（A1 B1 A2 B2 …）时，前 5 最多容纳某一份材料的第 3 名。所以"两份证据同时进前 5"
的充分条件是：**两份都在各自材料内前 3**。现在有 3 份证据进了前 3（cs9 第 2、cs4 第 1、
剪枝那题的 hy_kv 第 2），但它们分属三道不同的题，**没有一道题同时凑齐两份**
——这是分面召回换新精排后掉到 0/4 的原因（换精排前 cs4 与 hy_kv 都在前 2，还能拿到 1/4）。
要让其余题成立，必须把 8/9/32/61 推进前 3，这把问题顶回了模型与标注本身。

## 三、四条路径的实测与判定

### 方案 A：扩大精排候选池 —— 无效

池深提到 120、精排候选 100，跨讲仍 0/4。加上 2.2 的权重扫描，
可以确定：**候选池大小不是瓶颈**，扩大只是白付延迟（20→100 约 +3 秒）。

### 方案 B：分材料召回 + 门控 —— 最多值 1 题，不值得进产品

- 旧精排下实测 1/4（③），换现精排后连这 1 题也没了（⑧ = 0/4）。代价是 11 份材料 ×
  30 条 = 330 个候选逐对推理，约 15 秒/次；只挑全局前 10 命中的 2–3 份材料，也要 90 条、约 4 秒。
- 更关键：**要拿到这 1/4，必须先把问句拆成两个子问句**。检索层没有 LLM，"各自/分别"
  这种规则拆分不可靠；交给 agent 拆则变成"两次检索"，还得改评测口径才能量到。
- 判定：**不进产品**。一个最多省 1 题、换精排后归零、+4 秒、还要引入问句拆分的功能，
  收益不抵复杂度。

### 方案 C：换更强的双塔 —— 无效（对这道题）

`qwen3-embedding:0.6b`（1024 维，639 MB）换上去后，同一批块的精排名次几乎不动
（A/B 对照在当时的 base 精排下做：cs10 31→31、hy_flash 54→54），最终仍 0/4。
原因是融合权重 0.9 下最终顺序由精排决定，双塔只影响"能否进池"；
而进池早就够用了。

**这条结论只针对跨讲题。** 双塔对单材料题是否有收益没有测，也没动默认值——
换向量模型等于换全部数字的口径，不能顺手做。

### 方案 D：改分块（句对齐 + 重叠）—— 简单重叠无效

起因很具体：cs10 那块在 `...the memory for storing this KV cache` 处戛然而止，
`is going to exceed your H100 memory` 落到下一块——标注区间本身是完整的，是分块把句子切了。

离线单点验证（每块拼上下一块再精排）：`hy_kv`（Flash/KV 那题）从 25 升到 **5**，
其余 6 份全部变差（cs9 不变）——cs10（服务成本）42 → 66、cs4 1 → 13、`hy_kv`（剪枝）5 → 11、
cs10（剪枝）18 → 34、`hy_kv`（长上下文）5 → 8、`hy_flash` 62 → 64。**1 升 6 降 1 平**，净负；
而且升上去的那一份仍然不够凑齐"两份都进前 5"。原因也清楚：
块变长后精排的逐对打分被无关内容稀释。

判定：**不做整库重分块**。它要重嵌 942 块、重置全部指标、还要重验 65 个时间区间是否
仍被单块完整覆盖，换来的却是净负——性价比不成立。

### 额外测的两条：简繁失配、精排模型

- **简繁失配不成立**：问题用简体、何老师字幕是繁体，把问句转成繁体后名次基本不动
  （hy_flash 62→59、hy_kv 25→25、剪枝那块 5→3）。不是字符层面的问题。
- **精排模型是唯一有真实收益的杠杆**，但对跨讲题依然 0/4。详见下一节。

## 四、精排把哪些块排在了目标前面（决定性的原文证据）

`hy_flash [873, 916]` 在 69 块里排 **62**，p=0.000。排在它前面的三块，**每一块都字面出现
"Flash Attention"**：

> 2446-2490s（p=0.135）：那這個 scaled_dot_product_attention 你可以去設置說
> 你要用一般的 attention 的算法 還是用 **Flash Attention**…
>
> 2490-2535s（p=0.118）：唯一不一樣的地方 只是在 run Naive Attention 裡面 我們設定一個…
> 我們要 **Flash Attention** 來計算這個 QKV…

而目标块讲的是另一件事：**"一次都放到工作台上…你不可以做這樣的操作…這些數字跟 L 有關就不行"**
——通篇没有出现 "Flash Attention"，更没有"省的是哪一类开销"这句话。
换句话说，它用一个具体例子在讲"为什么不能把跟长度相关的量放进片上内存"，
而精排要找的是字面贴着问句的块。

`hy_kv [181, 224]`（讲"把 K/V 存下来不用重算"）排 **25**，p=0.001。排前面的两块：

> 2023-2068s（p=0.500）：所以他就試了不同的 這個 cache input 的方法…
>
> 2068-2111s（p=0.384）：**KV Cache 這個方法就是 儲存已經算出來的 Key 跟 Value…
> 唯一的代價就是一點點額外的運算**

第 1 名是同一材料里的另一段（讲各种压缩 cache 的方法），第 3 名则**比目标块更直接地
把"省什么、代价是什么"说成一句话**。

两件事叠加，就解释了为什么"证据在池里也排不上来"：

1. **词面缺失**：目标块可能整块不含问句里的关键词（hy_flash 全篇没有 "Flash Attention"）；
2. **同材料里有更贴问句的块**：标注选的是"某一次具体讲解/演示"，而精排偏爱"把结论说成一句话"的块。

**精排没有坏，它在按"字面与问句的贴合度"排。** 这不是能用参数修的东西。要"修"，只剩两条路，
都越过了本项目的红线：

1. 换一个更大、更贵的精排，赌它对具体讲解块的偏好不同——`v2-m3` 试过了，不改变结果；
2. 改标注区间去迁就排序结果——明确禁止（见第六节）。

所以跨讲题 0/4 的**如实结论**是：这 4 道题在"标注区间必须进前 5"的判定下，
用当前可用的模型与分块打不到。失败原因分三类：**词面缺失**（hy_flash）、
**同材料里有更直接的概括块**（hy_kv）、**分块把答案切断**（cs10 那块在
`...the memory for storing this KV cache` 处戛然而止）。

## 五、顺带发现的真实收益：精排换代（已采纳）

排查过程中试了更强的精排，对跨讲题无效，但对**单材料题**是这一轮最大的收益。
现默认是 `BAAI/bge-reranker-v2-m3-int8`（0.57 GB），同一套 83 题、同一向量、`rerank_candidates`
保持 20：全量 Hit@5 **0.807**、MRR **0.682**，pdf **0.857**、video **0.787**。

取舍与实测细节（int8 与全精度的差别、候选数为什么不能砍、逐题涨跌）写在
[检索口径沿革](retrieval-history.md#v5-精排换代2026-11-24)；
当前配置在代码里的位置与延迟代价见[检索对照](retrieval.md)。

**已采纳（2026-11-24 经确认）**：默认精排换成 `bge-reranker-v2-m3-int8`，
`docs/`、`README.md` 里所有带精排的数字都按新口径重跑。跨讲题结论不变——换了精排仍是 0/4，
所以这次换的是整体检索质量，不是跨讲题的解法。

## 六、明确不做的四件事

1. **不放宽 `targets_mode=all` 到 any。** 那等于把"跨材料对照"这道能力题删掉。
2. **不允许"相邻块算命中"。** `cross_kv_reduce` 有一块紧贴目标区间（差 1 秒），但那条讲的是
   attention sink，不是 KV cache 剪枝；算命中就是用错的证据蒙对。
3. **不改标注区间去迁就检索结果。** 65 个时间区间全部能被单个块完整覆盖，说明标注是可达的，
   问题在检索侧——这一条在四轮实测后仍然成立，反而是最该守的底线。
4. **不为了"让跨讲好看"把分面召回默认打开。** 它对单材料题是负收益（候选池被别的材料稀释），
   门控起来也只值 1 题。

## 七、留在仓库里的诊断工具

跨讲问题以后很可能被重新提出，所以把方法留下，而不是把结论留下：

| 脚本 | 回答什么问题 |
|---|---|
| `scripts/inspect_within_material.py` | 目标块在**它自己材料内**的 BM25/向量/融合名次 |
| `scripts/inspect_facet_recall.py` | 每材料取前 k 条合并、整池精排后的名次；含 k 与权重的扫描 |
| `scripts/inspect_ce_neighbors.py` | 精排把哪些块排在了目标前面（原文）；支持重叠、子问句、交错合并 |

三个脚本都走 `scripts/eval_assets.settings_for()`，向量模型只来自配置或 `--model`，
不会自己换模型造出第二套口径。

## 八、决定状态

1. **精排换不换 → 已定：换（2026-11-24）。** 默认值已改为 `BAAI/bge-reranker-v2-m3-int8`，
   当前全量 Hit@5 0.807、MRR 0.682，模型 0.57 GB，单次提问 3.28s（无精排 0.25s）。
   精排候选数保持 20。差值、备选方案与取舍理由在[检索口径沿革](retrieval-history.md)。
2. **跨讲题的判定口径 → 先待定（2026-11-24）。** 现有结论如实记为 0/4。
   如果将来必须有可量化的进展，可行的方向只剩两条：把跨讲题的标注改成"讲清同一结论的
   概括块"（需判断是否属于放宽判定），或允许 agent 端做两次分材料检索并把评测口径改成
   "两次检索的并集"。两条都动了判定口径，本次不做。
