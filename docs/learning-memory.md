# 学习主题接续与记忆管理

更新于：2026-10-20 09:53（Asia/Shanghai，UTC+08:00）。

上下文管理第三阶段已实现。记忆用于接续讲解偏好、学习目标和待解释问题；当前问题与用户明确修正优先。它不是自动建立的掌握画像，也不是把全部聊天搬到新会话。

## 网页使用

1. 创建会话，展开“接续学习主题与记忆”。默认独立学习，未开启跨会话记忆。
2. 创建学习主题，可绑定本空间的多份资料；不选资料可用于纯讨论。主题有独立ID，同名主题也彼此隔离；创建后的资料范围固定，需要不同范围时另建主题。
3. 选择主题、勾选接续并保存。设置在此会话持续生效，刷新和重启后保留；每个新会话仍默认关闭，需要再次选择主题。
4. 保存希望延续的讲解偏好、目标或待解问题。可以直接填写，也可以选择本主题的已完成回答作为来源；点击保存表示你确认这条记录。Agent的临时卡点判断不会自动变成长久记忆。
5. 在列表查看来源，修改、停用、重新启用或遗忘。资料已经更新的条目会提示暂停召回，需核对后修改保存以重新确认。

“整个主题”的偏好和目标可辅助该主题下的问答；限定某份资料的记忆仅在提问附带该资料的页码或媒体位置时参与召回。选中主题之外的资料时不召回该主题记忆。待解释问题还需要与当前问题有文字匹配，没有匹配时允许不召回。

记忆里的历史答案和页码、时间提示都是待核对线索。Agent必须实际读取资料，才能获得当前回答的来源跳转资格；原话回读不会变成当前视觉观察。

## 修改与遗忘的边界

修改、停用、遗忘和切换接续设置会使关联会话的旧摘要失效，并将既有回合移出后续自动重放范围。Agent从旧记忆推测出的会话目标、卡点和讲法也会清理；你在面板明确填写的状态保留。这个做法偏保守，会同时减少此前正常历史的自动接续，用户可指明旧回答来回读。

这样处理是因为仅从记忆表删掉一行，旧答案、工具结果或摘要仍可能重复它。当前不尝试逐句判断历史内容是否依赖某条记忆，而是用回合边界阻止自动带回。后续回合和新有效记忆可以继续积累。

记忆修订采用版本校验；过期页面返回409。任何关联且开启接续的会话正在回答时，记忆修改也返回409，避免运行中途换成另一份记忆。字幕等资料更新后，在下一个用户回合检查版本、清理旧派生上下文；已经发出的回答不会被中途撤回。

遗忘移除记忆正文及其修订内容，保留ID/修订墓碑，清除历史派生注入包中该条记忆的副本。原始问题、答案、工具观察和已生成的历史记录仍保留；明确询问过去的话可以回读，但不能据此重新启用旧偏好。这不是删除完整聊天、数据库备份或服务商日志的功能。

## 实现与接口

`memory.py`提供严格输入模型、SQLite主题/记忆/设置存储、版本校验与召回；`context.py`把本轮选择的记忆作为标注数据注入，进入原有预算估算；`agent.py`冻结本轮选择并记录ID/修订。旧回合的派生注入包不作为下一轮记忆来源。

先检查资料空间、主题ID、状态和资料版本，再做范围与文字筛选。文字匹配采用英文词与中文二元词交集，偏好/目标优先；最多6条、正文合计1800字符，每主题最多100条未遗忘记忆。它不是向量召回，也不把命中数量视为回答质量。没有增加嵌入服务或额外模型调用。

| 接口 | 用途 |
| --- | --- |
| `GET/POST /api/spaces/{id}/learning-topics` | 列出/创建空间内主题 |
| `GET/PATCH /api/conversations/{id}/context-settings` | 读取/修改接续设置，修改需revision |
| `GET /api/spaces/{id}/memories?topic_id=...` | 查看指定主题记忆 |
| `POST /api/spaces/{id}/memories` | 用户直接填写或确认保存，来源回答可选 |
| `PATCH /api/spaces/{id}/memories/{memory_id}` | 修改text或active/disabled状态，需revision |
| `DELETE /api/spaces/{id}/memories/{memory_id}?revision=...` | 遗忘并保留墓碑 |
| `GET /api/runs/{id}/context` | 查看各步选择的记忆ID/修订和历史边界 |

`recall_learning_context`仍可读取本会话原话；跨会话时必须使用本轮实际召回记忆明确链接的`source.run_id`，不能遍历主题下全部对话或读取任意空间。已停用或不匹配的记忆不开放这个入口。

## 验收与限制

```bash
uv run python examples/evaluate_memory.py --output data/evaluations/memory-m3-new
```

命令使用配置的真实模型并计费，输出目录须不存在，数据库、报告和资料均留在忽略的data目录。

本轮采用自编的两行归一化材料进行8个场景的真实兼容网关验收：来源查阅、默认独立、主题接续、同名主题隔离、偏好更正、停用、当前问题覆盖旧偏好、遗忘。8轮完成，10次模型返回，输入usage33344、输出1415，约53.15秒；没有为记忆单独调用模型。后续增加的派生副本清理、回读说明和界面标签调整通过工程检查，没有再重发这8轮。

人工对照结果：接续采用先2/4后符号，更正后采用先公式后3/9；当前要求两句、不举例时遵从；遗忘后明确没有可用偏好。输入快照显示默认独立、同名其他主题、停用和遗忘场景均未选择该记忆。这是开发过程复核，非独立盲评、真实用户学习收益或广泛效果基准。

工程回归95项通过，覆盖空间/同名主题隔离、范围与零匹配、版本冲突、资料变更失效、原始对话保留、派生注入清理、固定目标保留、来源回读授权及运行中修改拒绝。网页实际验证了主题创建/接续、刷新恢复、新会话默认关闭、记忆编辑/停用/重新启用/遗忘、来源回答回访；另发1轮短问答，按已保存偏好先给二维例子。

当前仍是本机单用户系统，空间边界不替代账户权限；多用户部署需身份与授权、租户隔离和完整删除策略。记忆筛选可能遗漏同义问题，主题范围不可编辑，[Agent Runtime RT1](agent-runtime.md)已支持刷新找回任务和取消；进程崩溃后的中间步骤续跑与正文流式仍待实现。
